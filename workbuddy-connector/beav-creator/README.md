# Beav Creator for the WorkBuddy Connector Marketplace

Upload the sibling ZIP to the WorkBuddy Open Platform connector form. The ZIP contains this directory's files at its root. This is an MCP connector package, not a `.codebuddy-plugin` marketplace plugin or a Buddy App configuration.

## What WorkBuddy can use

The package starts Beav's existing Creator MCP server and exposes its current tool catalog. It does not contain a separate media engine or copy the user's workspace into WorkBuddy. After connection, WorkBuddy can:

| Area | Available operations | Conditions |
| --- | --- | --- |
| Discover | Check Beav connection and capabilities; list workspaces and projects | Beav must be installed and the connector authorized |
| Creator data | List, search, read, create, and update supported knowledge, assets, manuscripts, and workspace resources | Direct calls require the selected workspace to be active in Beav; each tool's schema and permissions apply |
| Media | Call supported image and video generation, transcription, voice, and video-editor actions | Requires suitable source resources, configured model/provider or local dependencies, and any required project binding; some jobs complete asynchronously |
| Beav Agent | Delegate a creator task, follow its status, continue or cancel it, and inspect returned artifact references | Beav's Agent handles its own execution; an artifact reference should be read back before claiming a saved result |

WorkBuddy sees only the actions Beav currently exposes for the active context. `creator_capabilities` and the complete paginated MCP `tools/list` response are the authoritative inventory. Internal Agent control, Beav system settings, arbitrary absolute-path file access, and the full Beav desktop UI are outside this connector.

## User setup

1. Install a Beav release on the same computer as WorkBuddy.
2. Open Beav and select the workspace that WorkBuddy should use.
3. Explicitly authorize WorkBuddy by running the installed Beav executable with `extension prepare workbuddy --output json`. On macOS with the standard app installation, use:

   ```sh
   "/Applications/Beav.app/Contents/MacOS/beav" extension prepare workbuddy --output json
   ```

   On Windows or Linux, invoke the installed Beav CLI at its actual path. Do not paste the returned credential path or credential contents into WorkBuddy chat or the Open Platform.
4. Connect Beav Creator in WorkBuddy. The connector launcher reads the private MCP configuration generated by Beav and starts `beav mcp serve`; it never creates or refreshes authorization itself.
5. Verify `creator_status`, `creator_capabilities`, and `workspace_list`. Direct tools require the selected workspace to be active in Beav.

The connection is local to the user's computer. The Beav preparation grants WorkBuddy access to Beav business workspaces; users can revoke that grant in Beav. Long-running media operations may use a configured remote model provider, so local tool access does not imply local generation or free usage.

## Publication boundary

WorkBuddy's Buddy App documentation says automatically enabled built-in connectors must support OAuth MCP. This package uses Beav's existing explicit local grant and does not implement MCP OAuth, so it must not be described as satisfying Buddy App automatic binding. Platform review and a real installed-connector test are still required.

The launcher expects WorkBuddy's marketplace connector directory at `~/.workbuddy/connectors-marketplace/connectors/beav-creator` (or beneath `WORKBUDDY_CONFIG_DIR` / `CODEBUDDY_CONFIG_DIR`) and Beav's platform user-data directory. These paths match the current local WorkBuddy marketplace and Beav `extension prepare` output layout; they are not a substitute for an installed-host test on each target OS.
